# Authority rules

The Project Vault entry chain is `AGENTS.md` → `PROJECT.md` → the one Active ExecPlan → current domain records → cited evidence. Read the current working set first; follow historical references only when the task requires them.

`AGENTS.md` owns stable entry rules. `PROJECT.md` alone owns the foreground objective, identity, stage, resource registration, canonical writing sources, Active Plan reference, and Core pin. The Active ExecPlan owns completion conditions, scope, current risks and blockers, unfinished background registrations, writable paths, and the resume point. Its `latest_checkpoint` references historical entries under `plans/logs/`; it does not duplicate the objective or accumulate progress, findings, decisions, validation, and artifact lists.

Domain records own scientific intent, acceptance, provenance, evidence, Claims, decisions, and incidents. Action records own task state, bounded validation plans, candidate-bound check evidence, exact operation-scope grants, and blocker histories. Reuse an actual approval while its scope matches; a new session alone does not require new approval. Grants record user decisions and never replace operating system or execution platform permissions.

Only one current writer may edit a canonical record. Nonconflicting Actions may execute concurrently when their required resources are available and approved. Execution state derives from Action status. A downstream Action may depend on a separately accepted exact Artifact version; the producer need not be entirely closed. Unaccepted or changed file versions are not satisfied dependencies.

Necessary checks and attempt limits are set for each task. Stop when they pass. Exhaustion requires a recorded reasoned decision to revise, narrow, or pause. Preserve prior checks and resolved blockers. Run completion, Artifact acceptance, Action closure, scientific Claim approval, and external delivery are distinct facts; never infer scientific approval from a successful process.

A researcher-approved rebaseline updates the project goal, question, plan, and every unfinished Action's disposition together. Deferred, cancelled, and superseded work is not successful completion. Preserve historical research evidence and the reason for each decision.

`generated/` contains rebuildable views, not project truth. Summaries link to canonical sources. Checkpoints preserve actual work in history and update the next step; they do not commit Git. Report uncommitted project records when handing off.
